# 整体体验优化实施记录

维护中的方案及 25 项正常、压力、异常测试矩阵位于
[飞书文档](https://my.feishu.cn/docx/T902dXr8koRDJaxwhnDcMf0hnZf)。
这是整体体验优化任务。SQLite 是优先试验的存储候选，FlashDB 是正式对照候选，
尚未排除。采用某个数据库本身不构成验收通过。

固件地址和身份区不动，应用数据共用一个 1 MiB 池，配额只设上限，不预先切块。
凭据、待发送草稿和当前读取对象不被缓存淘汰。每项异常在故障清除后须回归主干。

## 共享配置池增量

配置、令牌、缓存归属、已读位置、配网标记和 Wi-Fi 配置已经接入同一 `/feishu`
1 MiB 文件系统。小型恢复记录使用双副本、代号、长度和 CRC 校验，不另划分区，
不按值长度分配工作内存；业务缓存仍由 SQLite 管理。恢复记录独立于可丢弃数据库，
数据库打不开时仍可读取联网与授权配置。配额不是物理切块；缓存写入为必要配置更新和
数据库日志保留 48 KiB 运行余量，必要写入可使用这部分余量。

先读回验证新记录，再仅删除旧 NVS 中明确的应用键，不擦除 NVS/身份/校准分区。
持久化迁移标记阻止旧令牌在解绑后重新导入；访问令牌和缓存归属与绑定代号关联，
更换应用、重新授权及撤销时隔离旧值。Wi-Fi 使用共享池恢复并设置为 RAM 存储，
旧 SDK STA 配置在新副本写入验证后才清空。主机通过 7.5/8 KiB 令牌导入/轮换、
账号隔离、撤销、迁移清理失败后的重启、数据库独立恢复和已读单调性用例。
原始 Flash 掉电及实际 SDK Wi-Fi 迁移仍需实机验证。

双副本层通过 20 个半写/空间不足位置，覆盖首写失败重试、单份损坏、冗余写失败、
同步失败恢复、范围读取和两份损坏时拒绝自动覆盖。数据库启用增量收缩，主机验证

## 模拟器 Wi-Fi 兼容性

PassportSim 1.0.3 使用已知 ESP-IDF 函数的指令指纹绑定 Wi-Fi 高层模拟（HLE），
将对应调用接到虚拟 AP 和宿主机 HTTP 桥。它没有完整重现物理无线电。
因此，修改应用也可能通过优化选项、链接布局影响 SDK 函数的最终机器码，导致识别失败。

此次引入 SQLite 后，其可写静态表改变了 GP 相对寻址范围；一个原本的单条 `lw`
变成 `lui` 加 `lw`，对应函数由 54 字节变成 58 字节，已知指纹不再匹配。
这说明模拟器拒绝绑定该构建，不能据此断言实机 Wi-Fi 损坏。
当前通过链接布局保持 SDK 的 GP 访问形式，且显式向堆分配器登记 SQLite 静态区。
`tools/verify_firmware.py` 同时检查静态区被 BIN 正确加载并排除于堆，避免只修指纹
却引入真实内存覆盖。应用固件分区地址未变。

每个模拟器报告保留准确 BIN/ELF 哈希和 HLE 绑定回执；SDK/编译器变更需重新验证。
更长期的模拟器改进应在指纹识别机制及支持的 SDK 构建集合上完成，而不是不断修改业务
逻辑迎合模拟器。Wi-Fi 射频、真实 TLS 和硬件重连仍需独立实机验收。

## 下一步提及处理方案

保持分块压缩的原始正文不可变，在共享数据库保存提及映射和稀疏逻辑字节检查点，
读取当前窗口时再解析名字，避免复制第二份全文及临时双倍配额。映射需覆盖正文
前/后出现元数据、超过8个提及、跨块/跨页、离线重开，严格匹配完整标记，不把
长标记的前缀错误替换。尾部响应异常时正文和映射均不得发布。映射不可用或
格式异常时保留原始正文和提及标记，不丢失消息。这是下一阶段方案，尚未实现。

## SPIFFS 按净收益回收

加密故障快照可在 RAM 模拟 NOR 中用相同 SDK 的 SPIFFS 源码重现：存在 1,076 个已删除页，却只有 29 个空闲页。原候选评分反复选中那些“回收删除页的收益，被额外重写对象索引页消耗”的块，净空闲页没有增加，随后无进展保护返回 FULL。SQLite 启动还需要清理一个残留 pin，所以仅避免重复设置 vacuum 不能打开这一份故障数据库。

本地 `components/spiffs` 覆盖仅修改候选评分：可用空闲页少于 128 页、且符合本机每块 15 个条目的布局时，将额外索引重写成本计入净收益。空间正常时的磨损均衡、原有搬移和提交顺序不变。其余实现与配置仍来自 ESP-IDF；CMake 校验原始 GC 源码哈希，升级 SDK 必须复核。工作区最多 15 组（90 字节），不动态分配，不迁移磁盘格式。

同一故障池的 RAM 重放中，日志创建成功，原有 21 个文件逐字节相同，SQLite quick_check 通过。这是主机模型结果，不能当作实机耗时或掉电验收。公开主机用例覆盖压力排名、正常排名不变和读取失败不写盘。真机验收及容量／延迟边界随具体固件报告记录。
