# 全局助手与协作写消息

小智激活后保留当前业务界面，可语音查询会话、读取消息、切换界面、编辑草稿。
还可调整支持的设置。发送须先展示预览，再由后续识别到的用户语音轮次明确确认，或使用实体确定键。

## 激活与统一界面

- 配置完成后的业务页，双按确定切换激活或退出。
- 顶部电量旁的“智”始终显示：未激活灰色，激活亮青色，呼吸周期两秒。
- 初始化成功后按成功音开关播放提示音。开机激活仍展示会话列表，不另开助手页。
- 顶部、底部分隔线贯通240像素，文字保留边距。
- 操作提示中的按键名称不单独着色。普通加载、缓存提示改成激活/退出快捷说明；
  错误和必要操作状态保留。正常/成功绿色、警告黄色、异常红色。

## 音频与工作线程

沿用一个业务工作线程管理持续WSS连接，不新增常驻助手或音效线程栈。收音、界面加载、
工具操作和回答播放之间保持16kHz音频时钟；服务端24kHz Opus回答在本地重采样。
收音队列和Opus解码器不同时驻留。激活期间麦克风保持开启，设备自己的播放不作为新指令。
这不等于声学回声消除，也不代表支持同时打断语音回答。

本地VAD保留启动前六个20ms帧。静默不会生成空白云端对话。安静时切换业务任务，若恰有
一帧语音开头到达，则保留前置帧并恢复收音，避免丢前缀。普通读取和三十秒一次的被动刷新
保留采集并让位于语音；电量每十五秒更新。纯口述、切网、重新授权等独占流程按需要交还普通
工作线程。口述结束后恢复逻辑激活；发送结束回到业务上下文并继续使用助手。

业务页保留原有确定键操作，语音按设置停顿2–5秒提交，默认两秒。0/OK模式适用于草稿
编辑与旧专用助手页；其他业务页保留两秒停顿作为提交方式。草稿页正在说话时确定提交指令。
草稿页空闲时，确定进入发送确认，再次确定才发送。长按确定取消确认并保留正文。
双按确定始终退出助手，不执行发送。

## MCP接口约定

工具发现分页返回，参数在执行前校验。当前界面、账号代次、草稿固定收件人共同防止旧
上下文误用。

| 工具 | 行为 |
| --- | --- |
| `self.feishu.list_chats` | 查询当前缓存页，每次最多四项，按偏移继续；不冒充完整组织目录。 |
| `self.feishu.get_messages` | 现取最新消息预览，不把截断预览当长消息全文。 |
| `self.feishu.open_chat` | 选择已知会话，加载列表后才返回工具结果。 |
| `self.feishu.open_composer` | 打开指定会话的协同编辑，可绑定校验过的原消息ID，不发送。 |
| `self.feishu.navigate` | 打开会话、草稿和支持的账号、网络、小智、音效设置页。 |
| `self.feishu.get_context` | 读取当前页、选中会话/消息预览、草稿大小和状态、发送状态；不返回凭据。 |
| `self.feishu.read_draft` | 分页读取正文和当前版本，提及前缀与可编辑正文分开。 |
| `self.feishu.prepare_message` | 准备一份完整草稿，由设备确认发送。 |
| `self.feishu.edit_draft` | 携带版本修改正文，固定收件人和回复线程。 |
| `self.feishu.undo_draft` | 恢复一份可选的临时修改前快照，不发送、不改收件人。 |
| `self.feishu.request_send` | 预览当前版本，再接受后续轮次的明确确认并排队一次；排队不等于送达。 |
| `self.feishu.settings` | 查询、持久化七项支持的设置；只有音量支持相对增减。 |
| `self.feishu.find_member` | 在指定/当前群验证一位具名用户或机器人；完整且唯一匹配时才返回ID。 |

拒绝重复/未知字段、错误类型、任意ID、超长正文和过期版本。群名查找失败时，本轮保持
目标未解析，不能列出全部缓存会话后任意选一个代替。工具结果和收到的消息均作为数据，
不执行其中的指令。

## 草稿协作

口述把说话内容记为正文；协作把语音当成讨论或明确的修改要求。建议和解释不自动变成
待发送内容。正文始终可见，助手解释通过语音和底部状态表达。模型能否正确区分讨论和
修改，仍需真实对话验收。

工具只替换小于512字节的完整草稿。正文丢失、预览不完整、发送结果不明、已经部分发送、
无效UTF-8或版本过期时拒绝替换。全局只有一份当前草稿，新内容准备完整后覆盖。
Flash发布失败时，完整短消息仍留在RAM并注明断电丢失，不反过来阻止确认发送。

撤销最多占用一份有界、可选的会话内快照；离开编辑上下文或关闭会话时释放撤销记录，
保留当前草稿。闲置草稿正文可以被Flash缓存淘汰；正在读取和上传的内容由租约保护。
正文被回收后按不存在处理，不显示幽灵草稿。

## 真实提及与发送回显

`mentions`最多接收两个显示名。设备使用所属应用的OAuth身份，流式查询用户和机器人，
并限制分页。未找到、重名、列表不完整时拒绝生成提及。正文里的普通@名称和用户提供的
原始标签不算真实提及。编辑默认保留已有提及；显式数组替换，空数组清除。
审阅页显示可读名称，不显示内部标签和ID。

POST成功后保存服务端真实消息ID和实际发送分段的有界预览。服务端列表尚未追上时，
通过短期、仅用于显示的回显保留新消息；服务端出现同一ID后去重，不作为虚构历史落盘，
三十秒后过期。真实结构化@投递和发送后的列表表现仍需在确认过的目标会话内验收。

## 音效与内存边界

成功音、失败音、按键音分别持久化设置，默认开启。短和声音效参考438：按键18ms、
成功48ms、失败42ms。合并待播请求，避免网络长任务结束后才响旧按键音。
激活时沿用现有音频所有者；未激活时由业务线程借用并恢复预热。
短按键音只抑制VAD误启动，PCM仍保留在前置队列，不擦掉用户语音。

安静监听时，采集线程只在原有包池保留最新六帧PCM6（120ms），不会把持续静音排入网络
待发送队列。检测到说话后先按顺序提交前置帧，再排入全部语音帧，不覆盖说话内容。
已开始说话的积压仍有明确上限，超限报告音频反压，不静默截断消息。

| 资源 | 上限 |
| --- | --- |
| MCP请求/响应 | 4096 / 2048字节 |
| 工具结果 | 640字节 |
| 临时PCM6队列 | 待命初始80槽，上传前恢复原120槽/2.4秒容量 |
| 可完整编辑草稿 | 最多511字节；工具正文另限160个Unicode字符 |
| 发出的提及 | 最多两个名称；用户列表最多二十页；固定解析器流式接收 |
| 撤销 | 一份可选、有界快照，离开上下文/会话后释放 |
| 分页URL | 首页复用小基串，非空游标才按需分配编码空间 |
| 音效记录 | 两字节版本化有效载荷，另有FlashDB和镜像元数据 |

小智激活期间，后台刷新仅获取每个会话的一条最新预览，避免预取八条完整消息。列表读取延后正文持久化，打开消息时按需加载正文。工具调用飞书HTTPS前释放回复Opus解码器，保留音频设备和连接。成员列表仅后续分页分配游标URL。实际峰值改善须以新一轮真机测量为准。

自动化小智诊断将回复与提示音音量强制设为零，继续执行解码和音频写入。真实听感和麦克风验收单独进行。

这些不是总堆占用数字。TLS、Opus、LVGL、DMA和线程栈也要计入。
Build、Host、Device与待人工验收项分别记录在[验证记录](../development/feishu-validation.zh_CN.md)。
合成输入通过不代表真实说话、听感、长期射频稳定或真实断电已经验证；不承诺所有场景都
保留20KiB可用堆。

协议参考：[小智WSS](https://github.com/78/xiaozhi-esp32/blob/main/docs/websocket.md)、
[飞书消息内容](https://open.feishu.cn/document/server-docs/im-v1/message-content-description/create_json)。

小智设置提供0—100音量的行内调整。四字节版本二复用原保留字节，旧版保留开机/停顿
选择并以音量60兼容加载；回复音量动态读取。启动显示呼吸标题和进度点，复用可关闭的短电子成功音。

业务页不因不可见的收音计时变化而重绘。采集线程读取四字节有效提交时机的原子快照，
不逐帧等待界面锁；无待播音效直接返回，任务轮询使用非阻塞界面快照。音频二进制写入
限两秒，低于原2.4秒队列预算；失败时关闭连接，不重放可能已送出的音频帧。


小智默认空闲十分钟后退出，可在小智设置调整；零表示不自动退出。真实识别到的说话、回复文字，以及正在说话、处理、播放会续期；静默保活和后台刷新不续期。到期仅取消助手占用的录音并释放麦克风，不中断独立的发送或听写任务。四字节第三版设置将超时打包在原设置中；旧版设置保留原值，超时默认十分钟。回复看门狗改为连续九十秒没有应用数据进展才超时，不再限制整个回复的总时长。退出日志区分到期、任务交接、取消、告别及错误；未留下日志的旧问题不追认原因。

底部“小智聆听中”固定位置，独立且预先创建的后缀标签随呼吸周期显示零至三个点，不重新居中文案，也不触发整个业务页面重绘。其它提示仍保持原布局和完整不透明度。


C3只有一个CPU，但LVGL界面/输入、录音采集和业务/网络工作由不同RTOS任务承担。语音回复解码与飞书操作共用现有业务线程。只有新的用户操作可以抢占已开始的播音：发送中止、释放Opus，等待停止确认最多三秒。MCP选择页面属于本轮回答，自动刷新和本轮合并暂存的读取都不会打断回答。普通读取期间保留原采集任务和有界队列，检测到语音便让位。明确的独占交接仍释放音频资源，连接故障执行有限恢复；不新增常驻工作任务栈。

原24KiB独立LVGL池可能在系统堆仍空闲时耗尽。现改用共享C分配器，不再额外预留独立池。构建时校验源码契约、生成局部替换，使字体绘制缓冲申请失败可返回，并清空已释放的缓冲指针；其它断言保留。一次申请失败可能少画一个字，后续重绘会重试。诊断版在实际回复播音期间注入该失败，并检查界面计时和真实返回处理函数继续运行。这不等于承诺系统完全耗尽时所有其它对象创建路径都能恢复。


语音发消息直接打开协同编辑，没有正文也可先商量。完整且同收件人的当前草稿保留；新建空编辑器使用可丢弃RAM草稿。空内容可读取编辑版本，但不能确认或发送。模型读取并修改当前版本，随后通过request_send打开确认预览，不产生POST；旧版本不能改动确认状态。确认时继续聆听，每十五秒发送一次WebSocket保活。后续语音轮次确认相同版本，或使用实体确定键，将发送任务交给普通工作线程，在WSS/音频清理后执行，逻辑助手激活随后恢复。识别/回复事件不再清空工作状态而造成虚假的聆听帧。原始连接失败仍需实际退出/错误日志才能归因。


## 连接生命周期与真实就绪

逻辑激活独立于单条WSS连接。连接恢复保留音频设备、当前页面和草稿，丢弃旧连接的
接收状态，重新协商hello与完整MCP工具列表。不重放录音、工具调用或飞书POST。
已完成的激活问候不重复；用户取消、告别和激活超时仍可终止恢复。最多快速重试两次，
真实稳定的聆听或回答进展可补充重试额度。

只有hello、初始化、最后一页工具发现和首个实际采集编码帧都完成后，才展示聆听中。
准备连接、问候、麦克风预热不能标记成聆听。仅恢复连接不延长空闲超时。

TLS证书正常校验后释放对端证书。业务网络工作轮询WSS接收，使SDK能够处理控制帧；
只主动PING不够。完整MCP请求等当前HTTP调用栈退出后才派发，不增加常驻网络线程。

夜间诊断先持久化静音和关闭三类音效，并读回校验。正式版保留这些静音设置，直到用户
明确要求恢复。固定种子场景区分冷读、缓存读、真实界面取消、草稿确认、内存/连接故障
注入、安静聆听与真实云端MCP调用；这些不替代实体按键、真实声学和实际投递验收。


激活与发送恢复（R26）：仅用一个布尔标志记住本次激活是否已发出问候请求。用户关闭后重新激活才清除；工作任务交接、内存恢复或传输重连均保留。自动恢复由现有工作循环处理，不重置激活超时。首次连接通过 MCP initialize 的 instructions 请求一两句简短回答；保留原有唤醒词，不将长提示塞入唤醒字段。这是模型提示，客户端可能不采纳，不保证严格字数。没有新增音频池或常驻任务。发送时保留接收方和正文，底部显示进度，同时仍释放语音资源。静默维护显示暂停聆听，不再误标成正在处理语音指令。现有按键组件的多按计数支持三按，本次没有新增快捷键用途。


待命持续采集（R28）：普通排队读取期间保留现有采集任务和固定120帧队列。后台定时器不再停止采集，电量I2C采样在采集继续运行时执行。助手激活期间将被动列表刷新合并为30秒一次，保留采集；主动切换页面和语音查询仍会联网。采集端原子发布语音起点标志，通过现有HTTP进度回调取消可取消的读取，保留队列中的开头用于上传。助手工作任务下的GET连接采用SDK异步open轮询，使TLS建立阶段也可让位。被打断的列表读取延后到语音之后，不新增音频池或常驻工作任务。独占发送/口述/授权/网络交接、实际断线重连和轮流播放仍是独立边界；本轮不实现播放时声学打断，也不承诺无限离线录音。真机验收需让实际HTTPS与注入语音重叠，检查原采集队列保留，再验证云端识别与恢复。


延后工作与回答归属：当前助手会话仅合并暂存一份读取，不放入普通界面操作队列。它在本轮回答结束、采集继续时恢复，新页面会淘汰旧读取。MCP选择页面是本轮回答的一部分，不能冒充新的用户操作去终止回答；只有真实用户操作才可打断已经开始的播放。采集期间收到的旧播放结束事件不能结束未来的语音轮次，实际开始上传及等待本轮回答前重置完成标志。上传音频本身刷新保活时间，避免上传中多余的显式PING。聚焦验收拒绝非预期重连及自动重放后才成功的结果。

工具完成语义（R39）：open_chat 在 MCP 回调内加载当前/缓存消息窗口，完成后才返回工具结果，不再等待完成播音。navigate 在回报前读取草稿列表。嵌套 HTTPS 前已释放 Opus 解码器，不增加工作任务、线程栈或音频池。普通后台读取仍保持采集优先、被打断后延后的策略。open_composer 未带收件人时，仅指已打开的当前会话或编辑器；列表中高亮的行不代表收件人。任务类要求简短回报结果，问答类简洁回答；这属于模型指令，不是强制的播音长度上限。全局小智接管时退出旧录音页，保留用户主动口述功能。加载在业务页内展示，仅当已加载行确属当前会话时才保留显示。

R40 控制能力：request_send 未带 confirmed 时展示当前固定的收件人、引用回复目标与草稿版本；只有后续识别到的用户语音轮次，才能以 confirmed=true 和当前版本确认。同轮自我确认、过期/空/不确定草稿、重复发送和满队列均拒绝。确认时继续聆听，接受后走现有 WORK_SEND 资源交接，不在 MCP 内嵌套 POST；已排队不代表发送成功，仍可使用实体确定键。open_composer 支持 reply_to_message_id，必须属于所选会话已加载窗口；未知或跨群目标不降级为普通发送。引用消息标识经草稿编辑保留并交给现有回复接口。settings 提供七项持久化配置：开机激活、停顿时机、音量（含相对增减）、激活超时及成功/失败/按键音。保存失败不发布新RAM值，本地并发修改优先。navigate 支持小智/助手/配对/飞书账号/网络/音效页面；打开页面不代表重置账号或修改凭据。不增加常驻工作任务或音频队列。

R46 队列按需分配：助手待命采集使用80个PCM6槽位，含前置帧共1.6秒，覆盖可取消读取的一秒轮询等待。检测到语音后先取消读取，再由现有工作任务在 listen/start 和网络写入前补上40个槽位，恢复原120槽/2.4秒的活跃发送积压容量。待命时不让这4960字节负载与冷读取TLS争抢内存；主存储块不移动，扩展块先原子发布，再把索引放入现有队列。普通口述仍启动时分配全部120槽。分配失败走现有音频清理，不新增任务、编码器或线协议。真机验收必须同时覆盖持续采集冷读取、上传前扩容、首句完整识别、无真实TLS分配失败及所有恢复检查。


## 资源归属与内存碎片

分配策略集中在HTTP、音频和BSP适配层，不让业务页面互相借缓冲。本轮保持持续待命采集
和原有交互，没有引入全局替换分配器，也没有新增长驻工作池。

| 所有者 | 分配生命周期与边界 |
| --- | --- |
| 流式GET | 握手后预留完整TLS接收缓冲，持有至响应结束，cleanup释放；WSS/POST保持原策略。 |
| 显式启用的HTTP客户端 | 仅禁止重定向、无请求体的GET：TLS后创建TX工作缓冲，未发完请求头时保留，发完后清零释放；POST不启用。 |
| 消息解析器 | 首块正文到达才创建6984字节工作区，晚于TLS和请求头缓冲；完成、取消、出错均释放。解析期间固定RX仍持有。 |
| 音频适配层 | 待命稳定80槽，上传前原子发布40槽扩展；活跃时的PCM6格式、采样率和积压容量不变。 |
| 显示适配层 | 保留原20行/9600字节单绘图缓冲；关闭内置TJPGD时使用厂家7168字节界面栈，启用内置解码时仍保留12288字节。 |

原来提前创建解析器，是为了防止动态RX释放后留下的大块空洞被占用。固定RX持有整个响应后，
这条绕行不再必要：延后创建解析器，从握手叠加阶段移走6984字节，不增加界面特例。
真机逐次校验分配顺序，真实TLS内存不足、看门狗、意外重连、界面栈余量不足仍判失败。

以下是可借鉴的基础设施，尚未在本项目实现：

- ESP-IDF已使用[TLSF](https://github.com/espressif/esp-idf/blob/v5.5.3/components/heap/multi_heap.c)。
  单换通用malloc，不能证明能获得更大的连续空闲块。
- [Zephyr固定块池](https://docs.zephyrproject.org/latest/kernel/memory_management/slabs.html)
  适合反复创建的同尺寸对象，避免池内外部碎片；代价是预留容量及块内浪费。
- [Mbed TLS分配钩子和缓冲分配器](https://mbed-tls.readthedocs.io/en/latest/kb/how-to/using-static-memory-instead-of-the-heap/)
  可隔离TLS分配，但仍需容纳同时存在的连接，并验证线程安全和失败恢复。不能围绕活跃连接临时切换全局钩子。

是否采用专用池，以实际存活对象、峰值及最大连续块测量决定。有限测试通过，不代表任意网络
抖动或无限运行下不会碎片化。已验收构建及待人工验收边界见R53验证记录。


## 正文读取与调度进展（R61候选）

正文加载中仍提供已选原消息ID，前提是已加载会话与当前会话一致。引用回复绑定这个校验过
的ID，不等待完整正文，也不替换成普通消息。最初一直处理的现场没有同期日志，不能仅凭
这一处目标定位修正就证明那次问题的全部原因。

被说话抢占的完整正文获取，加入与消息列表相同的会话内延后读取机制。正文提交后先展示，
再保存可选的消息列表快照。日志区分联网获取与本地翻页耗时，不打印内容或凭据。
长正文映射处理也检查现有工作所有者的进度回调，以便让位于语音；回调不嵌套执行业务工具。

FlashDB的RAM读取窗口可能绕过物理Flash读取，因此协作调度放在每次逻辑读取之前，缓存
命中也覆盖，由Flash适配层注册统一回调。连续CPU预算达到四毫秒后让出两个tick；回调
不能重新进入数据库或执行业务操作，保留存储串行化和CRC校验。这是基础层调度规则，
不增加界面特例，也不关闭看门狗。多块根记录按精确键、槽与代次预取，随后仍逐块
检查并校验CRC，复用既有的有界定位缓存，不跳过完整性检查。选定主机用例
（7KiB正文、180条无关记录）读取次数从990降到322，零写入；不代表真机时延。

R54在真实HTTP401后的凭据读取中抓到IDLE饥饿，匹配符号落在read_kv的CRC校验。
R55在原完整门禁中加入真实401/刷新、完整正文落缓存、12KiB正文四次随机页读及本群具名
机器人查询。是否正式验收以验证记录为准；候选方案或构建成功不代表真机通过。


### 错误响应与异步连接恢复

消息/成员GET可显式请求提取非2xx响应的根级数值code。错误响应最多解析4096字节，
工作区2080字节，仅在错误响应时分配，cleanup释放；不转交正文或媒体存储回调。
完整且格式正确的明确令牌失效码，才按原认证策略刷新一次；重复code、嵌套伪code、
类型错误、截断、超长和无关权限错误均不作为撤销授权依据，不重放POST。

当前ESP-IDF 5.5.3异步连接在初始阶段填充fd_set，select超时清空后未再次填充。
下一轮可能永久等待空集合，而TCP实际上已经连接。上游有同类[问题报告#19378](https://github.com/espressif/esp-idf/issues/19378)。
项目构建时校验原源码SHA256，生成局部esp_tls.c替代源，每次轮询重新装入fd_set；
EINTR保留重试，其他select错误明确失败。共享SDK不改，仍保留30秒总期限及语音取消。

主机测试复现原清空集合死路，并覆盖40次超时后的恢复、EINTR和硬错误。诊断版在真实
连接时注入一次清空集合超时并要求随后成功恢复；正式版不包含注入字符串。正常版与诊断版
分别保留实际生成源码及原始SDK副本，源码变化时配置失败，不静默套用旧补丁。

## 当前页面查新与启动交接（R69）

当前最新消息页在普通工作线程空闲时每2秒查一次最新预览，小智持有线程时为3秒。
预览未变不写消息缓存；新ID先显示，再补齐整页；尽可能保留原阅读选中项，不追加
较旧预览、重复消息和已删除条目。发现变化或约30秒后仍对齐整页，以补齐遗漏、编辑
与删除；后台不保存完整正文，长内容仍沿用打开时按需获取路径。这里是轮询间隔，
不保证任意网络请求都能在3秒内完成。

会话摘要在两种线程所有权模式下都只查询最新一条，小智会话列表刷新由30秒改为8秒；
仍为轮转批次，不是所有会话同时收到推送。

两段启动流程共用Flash中的ASCII图形。应用初始化阶段用临时全屏覆盖层，缓存会话
可用或初始化结束/失败时删除。先发布缓存会话，再读草稿索引；已有列表不再被连接
过程文案替换，失败可进入原来的错误/重试路径，不无限遮挡。

发送仍会暂时交还小智所有者，为飞书HTTPS腾出内存；结束后如果只剩可选历史刷新，
先恢复已启用的小智，刷新命令保留到采集准备好后处理。减少的是停顿，不承诺整个
发送过程中WebSocket始终保持连接。

## 授权重入（R72）

设置中的授权仍先保存请求再重启，以完整释放旧语音/网络所有者。入口会取消可中断的
后台读取，并只展示一条BOT授权准备文案。持久化写入成功后，用8字节RTC-noinit标记
这一次软件重启；它不含账号数据，也不是授权凭据。下一次引导入口消费一次标记，
必须同时满足软件重启、标识及反码匹配；冷启动、其他重启、损坏值都保留普通启动。
实际授权请求前仍需读取并校验持久化状态。

授权重入跳过启动音和装饰性最短等待，直接从准备页到二维码，不穿插普通开机Logo。
已经开始的存储提交仍须安全完成，网络也可能等待；不承诺零等待或完全不重启。

## 首次列表预览与正文缓存有效性（R74）

首次消息列表及历史页联网读取显式使用分页预览接口，保留服务端游标和有界文字预览，
不安装正文压缩/存储回调。打开正文时仍使用原完整消息获取及缓存路径；不含未解析提及的
完整短文本可直接展示，需要提及映射的内容则获取完整正文。

消息模型保存官方[历史消息接口](https://open.feishu.cn/document/uAjLw4CM/ukTMukTMukTM/reference/im-v1/message/list)
返回的update_time字段。只有调用方校验过的同账号/会话范围内，消息ID、创建时间、
非零更新时间与文本类型都匹配，且未删除、正文引用可用时，才复用缓存。版本缺失、
损坏或重复时保守地不复用，避免展示编辑前正文。

完整正文提交后先显示，再可选地更新正常列表读取所使用的分页缓存中的正文引用，
不再只写旧messages/chat缓存键。写入使用捕获的范围版本，缓存失败不隐藏已经可读的正文。
消息结构变化后旧的可废弃快照因单元大小不符自然失效，凭据和草稿格式不迁移。

会话末项短按下：服务端has_more为真时复用原有游标、缓存与网络分页工作线程；末页提示。
加载中的重复按下不追加分页请求，原长按翻页保留。


## 省电策略（0.2.1-r80）

省电以实际用户活动计时，后台轮询与保活不续期；物理按键、有效语音与回复、实际语音上传更新活动时间。自动策略固定闲置120秒后生效，熄屏时长独立设置。

| 设置 | 可选值 | 默认值 | 自动行为 |
| --- | --- | --- | --- |
| 闲置熄屏 | 2～10分钟 | 2分钟 | 关闭背光，首次唤醒动作及其尾随双按事件被消费 |
| CPU省电 | 否／是／自动 | 自动 | 闲置120秒后允许动态降频与自动轻睡眠，仍受工作及音频锁约束 |
| 后台刷新 | 仅前台／后台／自动 | 仅前台 | 自动在闲置120秒后停止定时读取，进入页面和明确命令仍可刷新 |
| Wi-Fi省电 | 否／是／自动 | 自动 | 闲置120秒后使用MIN_MODEM，不重新连接网络 |
| 麦克风预热 | 固定时长 | 60秒 | 释放codec、DMA与任务，归还缓存工作线程资源；被动刷新不重新预热 |

应用只初始化一次电源管理（160/40 MHz、允许自动轻睡眠），通过电源锁切换，不反复重配时钟或重启Wi-Fi。两个PM锁确保音频采集、播放和业务操作期间响应稳定；持续聆听仍占用音频，因此不允许CPU轻睡眠，熄屏与Wi-Fi省电则独立生效。实际语音在PCM上传前恢复交互网络性能，保活包不续期。实现依据SDK的[电源锁机制](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32c3/api-reference/system/power_management.html)与[无线调制解调器省电接口](https://docs.espressif.com/projects/esp-idf/en/v5.5.3/esp32c3/api-guides/wifi.html#esp32-c3-wi-fi-power-saving-mode)。

没有新增应用工作线程：现有UI计时器评估策略并切换背光和PM锁；现有业务或助手线程只在状态变化时调整Wi-Fi，失败退避5秒。GUI基础节拍由5毫秒调整为20毫秒。定时器、USB调试和外设锁仍可能限制实际睡眠时长；允许省电不等于已经测得电流下降。

设置采用新增ROOT_POWER键中的5字节版本化记录，不改变原有键值编号。缺失或损坏时回退默认值，不清除账号或记忆网络。UI沿用选择、进入编辑、保存的交互；写入失败会说明当前选择仅在本次运行中生效。

仅前台模式保留缓存可读，进入会话或列表时刷新，也覆盖从正文返回列表的路径。业务线程与助手线程的定时读取统一受策略约束；后台流量不唤醒屏幕，也不延长用户活动时间。预热到期保持锁存，直到焦点释放；音效播放也不会把过期预热重新启动。
