# 飞书消息终端产品与技术规格

本文是 ESP32-C3 AI Passport 飞书消息终端的实现基线。设备直接调用飞书 OpenAPI，不依赖手机、电脑或云端桥接服务。设备不运行 `lark-cli` 可执行文件，而是在固件内实现本产品需要的同等认证和消息 API。

## 1. 产品范围

本产品按用户确认定位为个人飞书终端：设备用授权用户身份读取会话和发送消息，发送者显示为用户本人。neo 等名称对应授权应用，选择或创建应用不会把发言身份切成机器人。机器人身份发送属于另一种模式，本实现未切换到该模式。

首个可验收版本只提供四项核心能力：

1. 显示最近会话，并用圆点标识本设备上次查看后出现的新消息。
2. 显示所选会话的最近消息。
3. 选择一条消息作为回复目标。
4. 录音、转成文字、确认后回复该消息。

首版不显示图片内容、不播放语音消息、不处理话题详情、不编辑已发消息，也不追求与飞书客户端完全一致的精确未读数。图片、文件、语音等消息只显示类型占位文字。

## 2. 首次使用和每次开机

设备不显示开发板演示菜单，也不要求用户先寻找 `Setup`。启动决策顺序固定如下：

```text
开机
 ├─ 没有可用 Wi-Fi → AP 配网页
 ├─ Wi-Fi 可用但没有飞书账号 → 飞书绑定二维码
 └─ Wi-Fi 和飞书账号都可用 → 会话列表
```

### 2.1 AP 配网

- 设备广播 `FoloPassport-XXXX`，屏幕提示连接无密码热点，并显示热点名和 `192.168.4.1` 备用地址；配网不要求扫码。
- 手机连接热点后进入中文配网页，选择 2.4 GHz Wi-Fi 并输入密码。
- 提交后设备在保留 AP 的同时尝试联网。成功则自动关闭 AP 并进入飞书绑定；失败则留在配网页并显示明确原因，允许修改后重试。
- 已保存 Wi-Fi 在开机 15 秒内无法连接时，自动回到 AP 配网，不要求重启。
- Wi-Fi 密码不出现在屏幕和日志中。

### 2.2 飞书账号绑定

- 通用固件不包含任何飞书 App ID/Secret。高级用户在授权前，通过物理 USB 或 Web Serial 在本地写入自己开发者应用的凭据。
- 设备随后显示属于该用户应用的设备授权二维码。目标飞书账号必须处于该应用可用范围内并同意所需权限；企业管理员仍可限制应用访问或权限。
- 屏幕显示飞书设备授权二维码和剩余有效时间。未扫码、二维码过期或服务短暂失败时，设备自动换新二维码，不进入永久失败页。
- 扫码确认后，只要设备安全保存了访问令牌和刷新令牌，就立即显示“绑定成功”，随后自动进入会话列表。用户资料或会话同步失败不能把已经成功的绑定判成失败。
- 重启后优先使用缓存令牌；只有飞书明确返回令牌失效且刷新也被拒绝时才要求重新绑定。DNS、TLS、超时或断网不能清除绑定。

## 3. 页面、导航和文案

常用路径只保留四个页面。加载、断网、空数据和失败均在当前页以内呈现，不新增中间页面。

| 页面 | 主要内容 | `UP` / `DOWN` | `OK` 短按 | `OK` 长按 |
| --- | --- | --- | --- | --- |
| 会话列表 | 会话名、最后一条摘要、新消息圆点 | 移动选择 | 打开会话 | 打开设置 |
| 消息列表 | 发送者、时间、消息摘要；所选消息展开到三行 | 移动选择 | 回复所选消息并开始录音 | 返回会话列表 |
| 录音 | 回复对象摘要、录音时长、音量提示 | 无 | 停止并转写 | 取消并返回消息列表 |
| 文字确认 | 完整识别文本 | `UP` 重新录音，`DOWN` 取消 | 发送回复 | 取消并返回消息列表 |

设置页属于低频维护入口，不出现在正常路径。它只提供“重新配网”和“解绑飞书”，解绑必须二次确认。

界面采用单层列表和留白，不使用多个卡片方块。全部用户文案使用内置中文字体；会话名、发送者和消息按 UTF-8 边界截断，不能显示成方块或半个汉字。底部固定显示当前页面可用按键，不用英文缩写。

## 4. 会话、消息和未读规则

- 使用用户身份令牌获取用户可见的 P2P 和群会话、最近消息，并以用户身份回复指定 `message_id`。
- 首次绑定后的第一次同步把每个会话当前最新消息作为基线，不把历史消息全部标成新消息。
- 以后每 30 秒轮询；若出现晚于本地已读基线的他人消息，会话显示一个新消息圆点。首版只保证“有/无新消息”，不承诺精确条数。
- 打开会话并成功显示消息后，才更新该会话的本地已读基线。仅选中会话不能清除圆点。
- 会话页保留最近 8 个会话，消息页保留最近 12 条消息。刷新后尽量保持原选中项；目标消失时选择最近邻项。
- 空会话显示“暂无消息”，网络刷新失败时保留旧内容并显示“网络不可用，正在重试”，不清空列表。

发送回复使用稳定的幂等 ID。明确失败时允许重试；若发送请求超时且结果未知，先刷新消息确认，不能自动重复发送。

## 5. 语音转文字回复

- 麦克风采集 16 kHz、16-bit、单声道 PCM，以小块流式发送，禁止分配整段录音缓冲。
- ASR 的租户令牌只在开始录音时按需获取，不能阻塞开机和会话列表。
- 用户按 `OK` 停止，静音超时或达到 30 秒也自动停止。识别文本为空时回到录音页并提示重新说话。
- 识别成功进入唯一的确认页；发送、重录和取消都在这一页完成，不再增加“操作菜单”页面。
- ASR 失败保留回复目标并允许重试。取消时关闭音频和网络流，不能留下后台任务。

## 6. 软件状态与错误恢复

系统状态机分为启动状态和消息交互状态：

```text
BOOT → WIFI_CHECK → AP_PROVISION → WIFI_CONNECT
                    ↓ success
       APP_CHECK → USB_PROVISION → QR_BIND → INITIAL_SYNC → CHATS

CHATS ⇄ MESSAGES → RECORDING → TRANSCRIBING → REVIEW → SEND → MESSAGES
```

所有网络请求通过一个认证感知的 API 客户端：

- HTTP 2xx 且业务码成功：提交结果。
- 明确的用户令牌过期：刷新一次，再重放原请求一次。
- 刷新令牌明确失效：保留 Wi-Fi，进入二维码绑定。
- DNS、TLS、断网、服务器 5xx：指数退避并保留页面、缓存和绑定。
- 二维码待确认：是正常状态，不计为错误；到期自动生成新二维码。
- 内存不足：释放本次请求资源并回到可操作页面，不擦除 NVS、不重启循环。

日志只记录状态、HTTP 状态码、飞书业务错误码、空闲堆和最大连续堆；禁止打印二维码参数、App Secret、访问令牌、刷新令牌、Wi-Fi 密码和消息正文。

## 7. 认证、存储和内存边界

- 固件和发布镜像不包含任何飞书 App ID、App Secret 或用户令牌。配网后，引导提供选择/创建应用的链接或二维码，再进行用户授权；物理 USB 导入保留为高级备选方式。
- 只有首次引导确认设备尚无应用配置时，才接受带版本号的 USB 配置协议。写入另一个应用时会清除上一个应用的访问令牌和刷新令牌。App Secret 和令牌不得进入日志或生成后的固件镜像。
- 访问令牌可能超过 7 KiB。TLS 必须先完成握手，再分块写入长 `Authorization` 头，避免同时保留多份令牌和大 HTTP/TLS 缓冲。
- 用户令牌用于会话、消息和回复。Internal ASR 使用另行取得的本人网页会话；当前录音流程不获取旧公开 ASR 接口的租户令牌。
- JSON 响应按上限流式接收；释放 TLS/HTTP 对象后再解析。UI 模型使用固定容量，所有超长字段按 UTF-8 安全截断。
- ESP32-C3 无 PSRAM。设计目标是在最重的 TLS + Wi-Fi 场景仍保留至少 20 KiB 空闲堆和至少 12 KiB 最大连续块；每个关键请求前后记录并做实机验收。
- 量产版本必须启用 Flash Encryption 与 NVS Encryption；开发固件也不得通过串口泄露秘密。

## 8. 开发顺序和验收门槛

实现必须按以下顺序完成，上一层测试通过后才刷设备：

1. 纯 C 状态机：启动路由、页面前进/返回、二维码超时刷新、认证错误分类、首次未读基线和发送幂等。
2. API/解析夹具：长令牌、分页、空会话、非文本消息、401 刷新、5xx 和截断 JSON。
3. 固件静态检查和完整构建。
4. 单次实机端到端验收。

实机验收矩阵包括：全新设备 AP 配网、错误 Wi-Fi 后重试、二维码不扫码自动刷新、扫码后自动进入、断电重启免扫码、断网恢复、令牌撤销后重新绑定、首次无假未读、新消息圆点、指定消息语音回复、空识别/重录/取消、发送一次且不重复、连续操作 20 分钟无重启和明显内存下降。

交付时分别报告 Build、Host tests、Device tests 和仍未验证项目，不能用“编译成功”代替实机通过。


## Internal 语音识别接入（2026-11-04）

替代通道使用设备所有者单独授权的网页登录态及内部网关命令 1305。摸金师2号成果包 SHA-256 为 `a39518a189fd0b4dea39326383b804a4a52b878a1382e7ecaef17e24cccc2e73`，未转移对方 Cookie。本人独立扫码登录已成功。主机凭据仅保存为 DPAPI 加密文件，不进入固件或日志。二维码生成、独立解码核验、有效性检查与发送连续执行，避免模型／工具间隔耗尽有效期。

固件 C 请求编码器和流式响应解析器已直接调用真实网关，两段合成 WAV 最终文字均精确匹配。响应命令为 ACK 1，成功码为 0／10000。实测响应 `sequenceId` 是识别版本，可以为零或重复，并不回显请求序号；必须用匹配的 Packet cid 与响应 sourceId 关联。请求序号仍从一递增。

录音使用内部二进制传输：空 BEGIN 先建立连接，再启动麦克风；每块采集 100 ms，六块还原为 PCM16k／单声道／s16le 后组成 600 ms 请求，最后发送空 END。具体压缩队列与内存预算见下文；不使用 Base64 或整段 PCM 副本。所有退出路径释放麦克风、连接和临时队列。

中间结果是累计预览，不按增量追加。普通录音已恢复持久化，512字节RAM缓冲只承载预览；完整验证的最终正文按原有至多300 KiB存储配额处理，并使用分页审阅。END 必须完整校验；超长或截断的中间结果不能变成有效草稿。失败／取消保留已有持久草稿，语音登录错误不撤销普通聊天 OAuth。

语音凭据使用共享池镜像配置键 8，绑定当前应用凭据代次，上限 4,096 个 ASCII 字节，拒绝请求头注入。重新绑定隔离旧语音会话。开发阶段通过即时读取的加密设备快照配置，逐文件保持已有数据不变；设备上自动刷新网页登录二维码尚未实现。

主机检查覆盖分片／非法 UTF-8、缺失或错误关联标识、零／重复识别版本、尾部错误、300 KiB、存储失败恢复及凭据持久化／绑定隔离。设备麦克风、资源峰值、断网与过期恢复应与主机结果分别验收。

### 小智源码对照及仍待完成的拥塞处理

参考版本：[78/xiaozhi-esp32，a78ca19](https://github.com/78/xiaozhi-esp32/tree/a78ca19d5bc9a12ee0853b9f509530276d36aa03)。小智把采集、Opus 编解码和网络发送分开；编码前队列为两个 60 ms PCM 帧，压缩后发送队列为至多 40 帧（2.4 秒）。编码／发送队列满时丢最旧帧；发送失败清空剩余待发包。WebSocket 持续发送二进制音频，并非每帧等待一次 ASR 结果。

历史故障是每个 200 ms 请求耗时 238／257 ms，缓冲又直到响应后才释放，耗尽约 0.4 秒余量。当前改为合包上传、及时归还和下述压缩队列；没有实现 Opus 网络传输或 Flash 音频队列。完整消息不能照搬丢旧帧策略而静默漏字。

`FEISHU_VOICE_AUTOTEST=1` 明确启用临时诊断，在真实 I2S 读取后覆盖公开合成音频，测试识别、持久化UI草稿和异常恢复，不发送业务消息。普通固件不包含夹具与自动操作。

### 普通录音恢复持久草稿

进入录音准备页不做前台草稿扫描。工作线程选择空的受保护草稿槽，或在明确重录时使用原槽；完整验证的END结果与目标/UUID元数据在共享池中原子发布。四槽已满或暂不可读时明确拒绝新录音，不覆盖已有内容。返回列表会保留草稿，可从草稿管理恢复。512字节RAM文本仅作预览，完整最终正文仍受既有配额限制并分页审阅，不能用超长中间预览加空END冒充完整结果。

离线确认发送会留在审阅页，提示草稿已保存，不排队发送。失败或取消保留旧草稿。POST前先持久化发送意图，SENDING/UNCERTAIN经重启保留，要求显式复核而非自动重发。历史上为SQLite/SPIFFS日志故障引入的RAM-only兜底，不再是普通录音默认路径。

### 压缩 RAM 队列实现（取代原始 PCM 排队）

采集改为每块 100 ms（1,600 个 16 位采样），在采集任务中编码为含独立状态头的 IMA 4 位 ADPCM，每块 804 字节；发送任务从队列取块，还原为 PCM，六块合并为已验证的 600 ms 请求。两个 PCM 工作缓冲共 6,400 字节，压缩队列按空闲堆临时分配 8～32 块（约 0.8～3.2 秒），预留栈及运行工作余量，结束全部释放。队列满明确失败，不丢弃最旧音频继续伪装成功。

ADPCM 是有损本地暂存，并非把新格式发给飞书；网络仍为每秒 32,000 字节 PCM。固定大小压缩队列提高的是抗抖动时间，不能无限承受持续低吞吐。C 编解码结果与独立 Python audioop 逐字节一致，两段样例往返后的 SNR 分别为 22.16／23.89 dB，真实接口识别文字均精确匹配；不能据此替代所有真人语音质量验收。Flash 音频暂存仍未实现。

自动真机回归增加一次 1.5 秒网络停顿后完整识别、一次 5 秒停顿的有界失败与随后正常恢复，再做 30 秒连续录音及实际界面工作队列的持久草稿。临时诊断完成后恢复不含夹具／自动操作的普通固件。

### SQLite pager 启动审计

仓库内 SQLite 3.54.1 源码对 auto_vacuum 设置语句生成 OP_Transaction 和 OP_SetCookie，即使已是 INCREMENTAL 也一样。每次打开库重复设置，会让缓存读取先依赖事务日志创建。启动改为先查询模式，仅在必要时设置；清理陈旧 pin 也先查询，避免无条件 UPDATE。

源码级故障 VFS 拒绝打开事务日志。无陈旧 pin 的已有库可以零日志创建尝试重新打开；显式设置／写入失败不丢失受保护数据；真正需要清理陈旧 pin 时仍安全失败，解除故障后正常恢复。这些操作维持普通 32 KiB 限额。单独的主机 quick_check 使用更大工作余量，不能充当固件峰值内存证明。

此前 xOpen 有界回收实验主机通过，但在既有 SPIFFS 故障池上无效且增加启动延迟，已撤回。保留事务日志和同步保证。本次启动修改不代表持续物理页耗尽已解决，也不替代底层存储对比。

### 经授权的诊断语音配置

诊断固件可额外启用 `FEISHU_VOICE_AUTOTEST_PROVISION=1`。普通聊天授权完成后，它通过本地 USB 接受一帧有界语音凭据，用实际镜像配置 API 写入当前绑定代次，清零临时缓冲，再执行既有静音 ASR 专项。接收窗口为 60 秒，只报告数值结果。主机读取所有者既有 DPAPI 状态，凭据不编译进固件、不进入明文快照。这用于验证原物理数据池上的实际配置写入，并非普通产品的登录／自动续登功能；普通构建排除接收器、样例和自动操作。

### 当前存储后端与全新配置

产品默认在原有 `0x370000` 的 1 MiB `feishu_img` 分区上使用 FlashDB，固件、字体和设备身份区均不移动。用户已明确允许删除应用数据后从头开始，因此不迁移 SQLite/SPIFFS 旧池，也不导入旧机器人的 NVS 凭据。空池创建空绑定状态，进入无密码配网热点，随后选择/创建应用并进行用户授权。SQLite 可通过 `FEISHU_STORAGE_BACKEND=sqlite` 显式选择，作为对照实现。

缓存层通过 `feishu_data` 对象接口和 `feishu_pool` 平台接口工作，UI 和网络代码不直接处理挂载、物理容量或恢复。配置与对象共用同一个串行引擎；分类逻辑配额与可丢弃缓存不会再划出多个分区。必要写入留有共享工作余量和两个擦除扇区的 GC 空间，保守估算仅在压力下重算。

对象目录为 128 槽，编码占 6,176 字节。压缩的 1 KiB 分块保持不可变，通过一次目录提交使正文/状态同时可见；ID 持久预留，暂存内容在中断后作为垃圾处理，阅读固定状态只留在 RAM。提及字典及批量稀疏索引支持有界文本读取。发布时使用临时目录缓冲，其完整产品/TLS 峰值必须实测，不能套用独立诊断镜像的空闲堆。

配置的两份镜像分别具有独立的 512 字节分块和 FRC1 头，支持 16 KiB 记录及零填充分段。四个小型 RAM 校验缓存只在原始介质修改或引擎重开前有效；实际取出的每个块仍校验 KV 校验和，避免每次读取一小段就重读整份配置。仅凭有效清单回收旧代次，当前正在写入的代次不得回收。

### IO、回收与调度保证

底层错误或短传输锁定当前打开实例，禁止继续写入；后续操作使缓存层撤销旧租约并重开，不能把 IO 错误当作整池擦除依据。未知格式和有负载的扇区禁止自动格式化。GC 中断后的 EMPTY 头，仅在整个扇区负载均已擦除、头部兼容且另有已识别原始扇区时，才允许补完成。

192 字节紧凑目录缓存扇区状态及已验证的尾偏移，头部查询不再遍历记录正文。主机回归跨扇区写入 140 个块时只读取 100 字节元数据。回收必须先成功搬完全部存活记录，才能擦除来源扇区。头部写入和记录搬运遇错立即停止。CRC 每次批读 256 字节，搬运使用 512 字节缓冲；命中的键也临时借用 1 KiB 读窗口。128 项正向缓存核对完整键长/键名并淘汰旧代次；固定 1 KiB 名称过滤器避免无谓的查无此键扫描。原始 IO 定期让出调度，避免长维护操作饿死显示、Wi-Fi 和看门狗空闲任务。
